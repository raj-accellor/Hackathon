Data Storage & Data Flow — file by file

How data comes in to this repository (NSE, Kite, NSDL, macro feeds, web search, uploads), where it goes (PostgreSQL, Redis, files under backend/var, the browser), and how it comes out (API routes → React pages). Every important file has a card with a plain-English explanation and a small example of the data at that point.

0How to read this document

Each file card has the same four parts. Snippets show only the shape of the data — a few keys, never the whole payload. All values are illustrative. Paths are relative to backend/app/ unless stated.

InWhat the file receives: a provider response, a DB row, a request body, a setting.
StoredWhat the file persists and where. "Nothing" means it only passes data along.
OutWhat it hands to the next file (or to the browser).
Snippet… = more keys of the same kind; lines starting # are explanations, not data.

Storage tags used throughout: DB PostgreSQL table · Cache Redis or in-process · Files disk under backend/var · Browser session/local storage.

1The big picture

Data moves in one direction through six layers. Connectors never write to the database; services decide what to store; the API is the only way out.

External sourcesNSE MCP ×2, Kite MCP, Tickertape MCP, NSE website/archives, NSDL, chart feed, MoSPI, FRED, web search
→
Connectorsconnectors/* — normalise each provider and attach provenance
→
Servicesservices/* — reconcile, compute (via domain/*), persist
→
StoragePostgreSQL · Redis · backend/var files
→
APIapi/v1/* — validate, rate-limit, wrap in an envelope
→
Frontendfrontend/src — fetch, validate, render

Two ways data is pulled in

  • Scheduled — workers/scheduler.py fires cron jobs (prices 19:30 IST, instruments 07:00, RRG every 12 h, themes monthly, alerts every 15 min, FII/DII 19:30 & 21:30). Results are stored.
  • On demand — a page asks the API; the service checks the cache, then calls the connector. Quotes, news, macro and movers are mostly served live, not stored.

Demo vs live

DATA_MODE=demo points the three MCP connectors at local mock servers (devtools/mock_mcp.py, ports 9100–9102), switches off NSE files, NSDL and web search, and flags every row is_demo=true. Storage and API code are identical in both modes.

2Where data lives

Four kinds of storage. Each piece of data has one home; the cache is a deliberate short-lived copy.

3File by file — in → stored → out

In the order data travels: wiring → connectors (data enters) → write-path services (data is stored) → domain maths → read-path services → API routes (data leaves) → frontend.

A · Wiring — settings, connections, schedules

These files fetch nothing themselves. They decide which sources, database, cache and timings everything else uses.

core/config.pyOne typed settings object

Reads .env once and gives every other file the same answers: which URLs, which cron times, which TTLs, demo or live. It also cleans values (a blank KEY= means "not set") and rewrites any Postgres URL to the psycopg driver.

InRepo-root .env, then backend/.env, then environment variables.
StoredNothing. Defines default paths under backend/var/.
OutSettings → read by container.py and the scheduler.
# .env line                                  →  what the app sees
DATABASE_URL=postgres://u:p@db/markets?ssl=true  →  postgresql+psycopg://u:p@db/markets?sslmode=true
DATA_MODE=demo                                   →  MCP URLs forced to http://127.0.0.1:9100-9102/mcp
PRICE_REFRESH_CRON=30 19 * * 1-5   # 19:30 IST, Mon–Fri
core/container.pyBuilds every connection once per process

Turns settings into live objects: DB engine, cache, each connector, rate limiters. Every service and route receives this Container (named c) so they all share the same connections.

InSettings.
StoredIn memory only. Tells the Kite client to persist its session to var/kite_mcp_session.json (live mode).
Outc.nse, c.kite, c.filings, c.nsdl, c.chart/cpi/fred, c.search, c.llm, c.cache, c.sessions, c.market_data.

Fallback: if Redis is configured but down in a local/test run, it swaps in the in-process cache and records why (shown on /health/ready).

B · Connectors — where data enters

Each connector turns a provider's raw answer into a common shape with provenance. None writes to the database. Shared plumbing: core/resilience.py (min-interval limiter, circuit breaker after 5 failures / 60 s reset, retries with backoff) and connectors/base.py (the result types).

domain/provenance.py · connectors/base.pyThe two shapes everything is wrapped in

Before you read any connector, know these: a DataPoint is one sourced value (with who, when, how fresh); a BarsResult is a price table plus where it came from. A missing value is None with a status and reason — never 0.

DataPoint(field="ltp", value=2898.45, provider="nse_mcp", source_id="cm_get_stock_quote",
          status="delayed", reason="NSE MCP live data is delayed by a few minutes", currency="INR")
DataPoint(field="bid", value=None, status="missing", reason="cm_get_stock_quote did not return bid")
BarsResult(symbol="RELIANCE", frame=<DataFrame date×OHLCV>, provider="nse_mcp", adjustment="unadjusted")
connectors/mcp_client.py · binding.py · parsing.pyShared MCP plumbing

Speaks MCP over HTTP: connects, lists the server's tools, and calls them. binding.py maps our intent to the server's own argument names (read from its schema); parsing.py tolerates different column spellings in the reply.

InA tool name + intent arguments.
StoredFilesKite session file only, when persistence is on.
OutThe tool's JSON payload, or a raised error (an error is never returned as data).
# binding: our words → the server's words
intent  {"symbol": "RELIANCE", "start_date": date(2023, 10, 1)}
bound   {"symbol": "RELIANCE", "from_date": "01-10-2023"}
# parsing: "ClsPric", "close", "CLOSE_PRICE" all become "close"

services/concall.py + domain/concall_score.pyCon-call follow-through analyzer

Reads last quarter's call for promises ("commission the plant by Q2"), then checks this quarter's call (and web search) for what happened. Uses the LLM when configured, otherwise a keyword heuristic labelled heuristic with Low confidence.

InTranscript PDFs from NSE announcements (or uploads); web results for the top 6 commitments; LLM output.
StoredDBconcall_transcripts (text + SHA-256), concall_analyses. FilesPDFs in the filings cache.
OutPer-commitment verdicts and an overall score.
{"commitment": "Commission the new unit by Q2", "importance": "high", "verdict": "partially_delivered",
 "evidence_source": "transcript", "grounded": true, "credit": 0.5, "weight": 3.0}
# score = Σ(weight × credit) / Σ(weight) × 100 → 62.5 "Mixed follow-through" (≥75 Strong, ≥45 Mixed)

Grounding: a quote not found verbatim in the transcript (or a cited web result) is excluded from the score; fewer than 3 grounded items → no score.

Three journeys showing the same value as it moves through files. Each hop names the file and what the data looks like there.

Trace 1 · A closing price, from NSE's file to the screener table

  1. workers/scheduler.py — 19:30 IST weekday: runs prices_job through jobs.run (lock + job_runs row).
  2. connectors/nse_filings.py — downloads the day's bhavcopy ZIP (cached on disk), unzips the CSV.

    price_bars (RELIANCE, 2026-10-23, close 2898.45, provider nse_bhavcopy_file)
  4. services/metrics.py + domain/* — reads 3 years of bars + statements, computes and stores today's snapshot. 
    metric_snapshots.flat {"close": 2898.45, "return_1w": 2.1, "pe": 24.3, "overall_score": 64.2}  is_latest=true
  5. api/v1/market.py — GET /screener?sort=overall_score validates params, loads latest rows.
  6. services/screener.py — filters, sorts, pages. 
    {"symbol": "RELIANCE", "values": {"close": 2898.45, "overall_score": 64.2}, "freshness": "fresh"}

Trace 2 · A live quote (never stored in the DB)

  1. pages/Instrument.tsx — calls GET /api/v1/instruments/RELIANCE/quote.
  2. services/market_data.py — cache check quote:RELIANCE. Hit → returned with "cache": "hit", done.

5Where data is filtered

"Why isn't X showing up?" is answered by finding which layer dropped it.

LayerFile(s)What gets dropped or flagged
1 · At ingestionmarket_files.py, ingestion.pyUnknown symbols, series other than EQ/BE, non-positive closes, inactive instruments, out-of-scope universe (UNIVERSE_SCOPE). Demo rows always flagged.
2 · Per requestapi/v1/*, screener.pyInvalid params (422), non-allowlisted sort fields, >25 filters, page size >200, date ranges >3 years for flows. Missing metric → excluded and counted.
3 · In computationreconcile.py, theme_dsl.py, metrics.pySource conflicts recorded with the winner; theme exclusions stored with reasons; stale data labelled; missing metrics leave the pillar denominator (not scored as 0).
4 · Protectionapi/deps.py, main.py, kite_mcp.py, tickertape_mcp.pyRate limits per bucket, 5 MB body cap, optional bearer auth, same-origin CORS, read-only tool allowlists.

Rules data follows

  1. Connectors fetch; only services store.
  2. Every value carries provider, retrieval time, status and demo flag.
  3. Missing is None + reason — never 0, never guessed.
  4. Scheduled work stores; on-demand work mostly serves live through the cache.
  5. Every write path is an idempotent upsert on a unique key.
